## R1：研究数据与单元执行基础

1. 更新共享 schema：可变 plan.version、动态子问题、带引用 Finding、按 unitId 归属的查询与全局预算；移除 round/maxRounds/maxQueriesPerRound。
2. 复用任务/来源/报告三类存储，增加所需的 typed JSON 与单元结果幂等回执；保留报告/终态原子提交和取消许可检查。
3. 通过官方 createTool 接 searchZhihu、授权的 searchWeb、readSource；工具上下文绑定任务和单元身份。readSource 只读已存摘要。
4. 实现 Researcher Agent 的隔离工具循环与结构化发现；模型每一步、搜索请求和未知失败均正确计量，调用前原子预占，完成后结算。

交付：单个调查单元能围绕一个问题自主查证并保存真实来源和 findings；不创建另一套通用 Agent loop。该阶段实现目标架构的一部分，不临时退回旧轮次方案。

## R2：主管、并行调查与核验回流

1. 主管生成粗计划，并基于证据新增/调整/关闭问题；通过唯一应用命令合并单元结果与更新全局计划。
2. 用 Mastra 官方 foreach/循环等能力执行最多三个单元，独立上下文、共享去重与预算；有依赖的调查在发现出现后再创建。
3. 以子问题覆盖、条件/反证、策略多样化后的资料饱和与预算决定收尾。全局没有固定轮数，单元额度用尽不代表整个任务结束。
4. Writer 用 findings 与原始摘要生成报告，应用派生来源引用；Verifier 检查关键断言，必要时一次定向回查，再改写并复验。
5. 使用开发方案第 7 节默认预算，全部角色共用一份额度；不能把 Agent.generate 当作一次模型请求，不能让并发单元各拿全部额度。

交付：一个完整的主管/调查单元运行流程，研究可以因新发现改变方向，最终报告可回溯。无需先完成 A/B、预算曲线或多题 benchmark。

## R3：接口与可靠交付

1. 接创建/列表/详情/取消/来源/报告/Markdown 路由，前端轮询读取新的目标 DTO；研究进度展示 researching/repairing 等真实阶段，不伪造轮次或百分比。
2. 核对并发预算预占、取消迟到提交、幂等完成、保存先于框架收尾、重启 interrupted 等核心边界，复用已有最小场景。
3. 执行受影响类型/后端构建和主链路检查，明确框架原语验证、fixture 和真实服务结果的区别。不要求用户投入手工对照测试。
4. 同步实际配置、运行命令与实现状态。没有真实服务配置时把真实效果注明未验证，完成不依赖凭证的工作；不把等待大规模质量评测设为架构阻断。

交付：可以按说明运行的研究后端、当前契约、可靠停止与保存语义。未获明确提交任务时不自行提交或推送，保留他人改动。

## 当前范围的终点

R1–R3 都只服务深度研究。聊天、OAuth、私人资料、用户编辑计划、任意步骤恢复、全量索引、SSE 重放、成果版本、桌面集成和备份不加入本任务。[质量案例](quality-cases.md)用于后续优化，不能因没有对照实验而重新打开已经确定的架构选择。
