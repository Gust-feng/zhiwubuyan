# 知无不言 · 产品说明计划书

> 一个围绕知乎公开内容构建的知识研究工作台

---

## 一、产品定位与场景价值

知乎沉淀了海量真实的经验分享、条件博弈与异议反例。然而，面对一个复杂问题，用户往往只能逐条翻答案，缺乏将多个立场系统整合、形成可信结论的工具。

**知无不言**正是为此而生：它把知乎的公开内容转化为可被 AI 主动检索、分析与归纳的研究素材，最终向用户交付一份带真实来源引用的研究报告——而不只是一次对话。

**核心使用场景：**

- 做购买决策前，想看懂知乎上不同用户的真实评价与分歧点
- 研究一个政策、行业或技术问题，需要多角度汇总而不是单一答案
- 想快速了解某话题在知乎社区中的主流认知与少数派声音

## 二、功能概览

### 1. 热榜信息流

首页展示知乎每日热榜，无需登录即可浏览，帮助用户掌握当日热点。

### 2. 深度研究

用户输入一个问题，系统自动制定研究计划，分轮检索知乎内容，分析依据与分歧，补齐缺口，最终生成附带来源引用的 Markdown 研究报告。

| 档位 | 实现方式 | 适用场景 |
|---|---|---|
| **Pro** | 单次调用知乎直答（zhida-agent），秒级返回 | 快速问题、轻量查询 |
| **Ultra** | 自研引擎：主管 + 并行调查单元 + 核验回查，最长 45 分钟 | 复杂问题、深度研究 |

> 网页端承接 Pro；Ultra 需要长驻进程，在本地运行面可用。

所有报告：
- 来源引用真实可点开，摘要标注为摘要，不冒充全文阅读
- 高赞仅用于排序参考，不等同于结论真实
- 重要结论明确提示用户回原文核对

### 3. 众声（看山整理）

把同一问题下不同立场聚合呈现，帮助用户快速理解"支持侧说什么、反对侧说什么、条件侧说什么"，而不是只看排名最高的那一条。

### 4. 成象（概念动画）

用户输入一个概念或一句话，产品先从知乎检索相关摘要作为参考资料，再由模型产出一份**可离线打开、分步讲解的单文件 HTML 动画**；结果可在浏览器中播放、下载存档，生成历史可查。

名字取自「在天成象」——概念成形，可见为象。

**核心流程：**

1. 取料：用主题检索知乎，取前 6 条摘要注入提示词（校准事实与讲解角度）
2. 生成：调用 OpenAI 兼容模型，产出完全自包含的单文件 HTML（内联 CSS / JS / SVG，无外链）
3. 安全加固：自动移除所有外部引用，浏览器端再用 `<iframe sandbox>` 二次隔离
4. 校验与修正：结构不合格时整份重做一次，仍不过则如实失败
5. 落库：生成成功即保存记录，可列表读取与删除

**边界说明：**
- 摘要不等于全文，动画质量受模型能力约束，不承诺讲解正确性
- 取料失败（限流 / 额度耗尽 / 无结果）时自动降级为凭模型知识生成，如实标注，不阻断流程
- 不支持动画内部编辑、逐帧控制或导出视频

### 5. 我的知乎

登录后可访问个人关注动态、收藏内容等个人化数据，结合首页直答与深度研究使用。

## 三、技术方案

### 3.1 整体架构

```
用户浏览器
    ↕ HTTPS
Vercel（静态前端 + Serverless Functions）
    ↕ 开放平台 API / OAuth
知乎开放平台
    ↕ REST API（Redis 缓存）
Upstash Redis（登录会话 · 限流 · 热榜缓存）
```

本地运行面额外承接 Ultra 自研引擎，通过本地 Node 服务 + SQLite 持久化研究任务与报告。

### 3.2 深度研究引擎（Ultra）

采用**主管 + 受限并行调查单元**架构（基于 Mastra Agent + Workflows）：

```
ResearchTask（顶层 Workflow）
├── Supervisor（主管 Agent）
│   ├── 拆题 & 制定动态计划
│   ├── 调度调查单元（最多 3 个并行）
│   └── 核验 & 触发定向回查
└── Investigation Units（调查单元，并行）
    ├── 知乎公开搜索（每次 ≤ 10 条）
    ├── 全网补证（允许时调用，≤ 20 条）
    └── 证据去重 & Finding 提取
```

- **单一事实源**：主管是计划唯一写入入口，产品 SQLite 保存研究内容与最终报告
- **证据约束**：内容身份 + 文本哈希去重；缺少可打开 URL 的结果不进入可引用证据
- **预算控制**：任务级时间预算上限 45 分钟；超时后标记 interrupted，不自动重放

### 3.3 Pro 研究（Serverless）

单次调用知乎直答 `zhida-agent` 接口，秒级返回，全程在 Vercel Serverless Functions 内完成：

- 需登录 + 纳入限流（默认每 60 秒 20 次）
- 不落库，刷新后不恢复历史任务
- 界面明确标注内容来自直答生成，不混同有引用的研究报告

### 3.4 登录与安全

- 知乎 OAuth 授权跳转、令牌交换与会话全部在服务端完成，前端不持有凭证
- 登录会话存于 Upstash Redis，跨 Serverless 实例共享，不因冷启动随机失效
- 消耗开放平台额度的接口（直答、众声、研究 Pro）统一限流

### 3.5 技术栈

| 层 | 技术 |
|---|---|
| 前端 | React + Vite，部署于 Vercel |
| 后端（Serverless） | Node.js Serverless Functions |
| 本地后端（Ultra） | Node.js 本地服务，端口 4301 |
| AI Agent 框架 | Mastra core + libsql adapter |
| 概念动画模型 | OpenAI 兼容 chat/completions，BYOK（优先 `ANIMATION_MODEL_*`，回退 `MODEL_*`） |
| 持久化（本地） | SQLite（via @libsql/client） |
| 缓存 & 会话 | Upstash Redis |
| 知乎集成 | 知乎开放平台 REST API + OAuth |
| 部署 | Vercel，自定义域名 gustfeng.dev |

## 五、知乎社区场景适配说明

- **内容取材全部来自知乎公开数据**，通过官方开放平台接口合规获取
- **知乎独有价值**在于真实用户的经验、条件判断与异议，产品设计以"分歧可见"为核心，而非只呈现高赞共识
- **众声模块**直接对应知乎"同一问题下多元回答"的社区特征，把知乎的内容组织形式转化为用户可直接消费的视角地图
- Pro 研究借力知乎直答的知识积累，Ultra 研究把知乎内容作为一手证据源系统取证——两条路径都将知乎定位为**可信知识的原产地**，而非仅仅作为搜索结果的来源之一
