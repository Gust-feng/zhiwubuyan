# 产品架构基线

## 目标

本项目将知乎开放平台提供的能力统一接入产品，由服务端 Agent、工作流和界面组合出可检查、可保存、可重复运行的用户体验。知乎接口是能力来源，产品价值来自能力编排、证据组织和研究工作流，不把平台接口直接暴露成聊天协议。

## 产品形态

产品**只交付网页端**（Vercel 静态前端 + serverless 函数）。网页端承接深度研究 **Pro**（单次知乎直答，流式输出，耗时受上游检索与生成影响，见 [ADR-0012](decisions/0012-pro-streaming.md)）；自研 **Ultra** 引擎需要 45 分钟级长驻进程与本地持久化，只在本机运行面执行，代码冻结保留、不再作为交付能力（见 [ADR-0011](decisions/0011-pro-only-freeze-ultra.md)）。形态取舍与桌面端处置见 [ADR-0008](decisions/0008-web-only-server-hosted-research.md)。

桌面端（Electron 壳、安装器与相关构建）**冻结保留在仓库**，不再构建发布、不再作为能力依据；`dist:win` 等脚本仍可运行，但不属于交付路径。

自研 Ultra 研究引擎同样**冻结保留在仓库**（`src/agent/**`、`src/backend/**`、引擎主体与 Mastra/libsql/proper-lockfile 依赖），不再作为交付能力、不新增投入；本机 `pnpm dev` 仍可运行它，`verify:research` 继续校验它，防止冻结代码在原位腐烂。

## 工作台布局

当前工作台的信息架构、页面职责、布局与扩展规则统一维护于[工作台核心布局设计](../design/核心布局设计.md)。首页采用知乎内容信息流，各功能板块独立；本文继续维护业务与存储边界。布局文档的更新不代表前端改造或后端接入已经完成。

## 后端详细设计

当前只交付深度研究后端，范围按 [ADR-0005](decisions/0005-deep-research-mvp-scope.md)，运行架构按 [ADR-0006](decisions/0006-supervised-research-runtime.md)。直接按[开发方案](../deep-research-development-plan.md)、[任务清单](../research/implementation-tasks.md)和[API](../backend-api.md)实施，不等待多方案 A/B 决定架构。

一个 ResearchTask 对应一个 Mastra 顶层 Workflow；一个主管围绕动态子问题分配最多三个并行调查单元，单元使用官方 Agent 工具循环。用户问题、来源权限和预算固定，内部计划可变，前端只读展示。研究策略不使用固定总轮数或固定每轮查询数。

产品研究模块拥有任务、不可变来源与报告。计划、带证据的 findings、覆盖分析、查询记录和单元结果回执保存为有类型 JSON。主管通过唯一应用命令更新全局计划；单元只提交材料、发现和建议。Mastra 拥有阶段和活动单元执行，产品覆盖判断不构成第二套执行状态机。

预算在模型每一步及搜索发送前原子准入/预占，全部单元共享；取消阻止新调用和迟到写入。报告核验可触发一次定向回查，修复后再次核验。报告与 completed outcome 同事务提交，重启未完成任务标记 interrupted，不自动重放。

Ultra 的单活动顶层任务、HTTP 轮询、服务端数据和云端模型边界继续保留。当前不做聊天/Memory、私人资料、用户编辑计划、任意步骤恢复或 Ultra SSE；Pro 单次请求使用 SSE 输出，断开即中止，不提供事件重放。OAuth 登录已在网页端接入。下文平台能力与已有约束不构成研究前置；已存在功能和并行开发代码保留。

## 两层边界

### 第一层：知乎能力适配层

这一层只处理知乎相关的数据和接口契约，负责把官方 HTTP / MCP 能力转换为稳定的内部能力接口。

建议按能力域拆分：

| 能力模块 | 覆盖能力 | 主要职责 |
|---|---|---|
| `content` | 知乎搜索、全网搜索、热榜、直答 | 请求参数、响应字段、流式解析 |
| `user` | 创作、关注、收藏夹、近期收藏 | 身份上下文和分页 |
| `knowledge` | 知识库列表、内容列表、检索、文件上传 | 知识库 ID、游标、上传状态 |
| `quota` | 统一额度查询 | 额度字段和能力映射 |
| `auth` | Access Secret、OAuth token | 凭证读取和身份类型，不混用凭证 |
| `event-content` | 故事、知识赛事内容 | 独立域名、赛事边界和归属信息 |
| `mcp` | 搜索、热榜、直答 MCP | 仅作为可选传输适配，不产生第二套业务事实 |

适配层的约束：

- 统一处理 Base URL、请求头、PascalCase 参数、`Code/Message/Data` 响应外壳和时间戳。
- 保留官方字段和未知字段；只在能力门面处转换为产品内部 DTO。
- 不导入 Mastra、UI、路由或本地产品数据库。
- 不在这里编排多个能力，不决定产品文案，不直接生成最终答案。
- HTTP 是首选接入方式；MCP 作为传输扩展。MCP 返回的文本/XML 必须先转换为同一内部结果模型。

### 第二层：本地产品层

这一层是软件自身的功能，包含 Mastra Agent / Workflows、Application command、权限/额度策略、缓存、审计、持久化和 UI DTO。

- 使用 `@mastra/core` 的 Agent、工具与 Workflows；模型接入走官方支持的模型路由/provider，不重写工具循环。
- 工具与工作流步骤只调用本地 Application command；Application command 再调用第一层能力门面。框架定义集中在 `src/agent`，不向应用领域或 UI 暴露内部类型。
- 深度研究的计划、取证、评估、撰写与审阅由 Workflow 编排。确定性操作直接调用业务命令，需要模型判断时调用 Agent；步骤不对应聊天 Run。
- 当前仅用 `@mastra/libsql` 保存工作流快照，产品保存研究事实与框架引用，不直接读写框架内部表。会话历史与 Memory 属于后续独立工作。
- 产品 schema 和工具参数使用 Zod；版本、事件、错误和状态以结构字段表达。
- 调查单元通过官方 createTool 自主搜索与读取已存来源，工具内部调用应用命令；任务/单元身份从可信上下文绑定，不让模型更换任务。
- UI 只依赖产品层 DTO，不读取知乎原始响应，不拼接请求参数。
- `zhida` 是知乎的一项内容生成能力，可作为工具或后处理器；它不是主 Agent 的模型适配器，也不承担工具循环。

## 数据流

```text
HTTP -> 研究应用命令 -> 顶层 Mastra Workflow
  -> Supervisor：初步拆题、计划更新、调查分配、收尾建议
  -> Research Units：独立上下文，官方工具循环，最多三个并行
     -> 工具 -> 应用命令 -> 知乎 adapter / 来源读取
  -> 来源与 Finding 合并 -> Supervisor 重规划
  -> Writer / Verifier -> 一次定向回查（需要时）-> 改写与复验
  -> 产品事务：报告 + completed outcome
```

产品库保存任务、来源、报告和有类型研究内容；Mastra 文件存储保存执行快照，框架步骤传递小型 ID 与控制结果。原始摘要、累计证据和完整工具结果不反复塞入框架快照。

## 桌面分发边界（冻结）

本节描述已冻结的 Windows 桌面壳，仅作历史与恢复参考：产品只交付网页端，桌面端不再构建发布（见 [ADR-0008](decisions/0008-web-only-server-hosted-research.md)）。

- Windows 桌面壳只负责进程生命周期、单实例窗口和加载本地工作台产物；它不是业务能力、凭证或持久化的 owner。
- 渲染器保持沙箱、上下文隔离和关闭 Node 集成；需要原生能力时，只能以明确、窄化的 preload 接口暴露，不能把 IPC 或 Node API 直接交给 UI。
- 外部网页不在桌面窗口内加载；工作台发起的 HTTP/HTTPS 链接交由默认浏览器打开。
- Windows 安装包仅安装应用程序、快捷方式和卸载登记；卸载不删除 Electron 用户目录或工作台偏好，未来如需清理产品数据必须先定义明确的 owner 与删除语义。

## 能力复用原则

平台能力全部进入能力目录，但按用户任务按需调用：

1. 公共检索：知乎搜索、全网搜索、热榜。
2. 生成辅助：知乎直答，用于摘要或补充，不替代来源检索。
3. 用户上下文：创作、关注、收藏夹、近期收藏；个人档案由用户快照与规则组装派生，只用 `user_data`，不调用生成式模型（见 [ADR-0010](decisions/0010-personal-archive.md)）。
4. 私人知识：知识库浏览、RAG 检索和明确授权的单文件上传。
5. 运营控制：额度查询、错误降级、缓存和请求去重。
6. 可选扩展：MCP 接入和赛事故事/知识内容。

## 当前交付与后续方向

当前交付为**深度研究**，分两条实现路径（见 [ADR-0011](decisions/0011-pro-only-freeze-ultra.md)）：

- **Pro（网页端交付）**：一次知乎检索（明确开启时补一次全网检索），真实摘要作为参考资料提供给单次 `zhida-agent` 生成，SSE 输出、不落库。资料与正文一起可读，但不冒充已核验报告；详见 [ADR-0013](decisions/0013-pro-reference-material.md)。只有正常收齐输出后才能完成，停止或断流保留部分正文和资料但不标为成功。
- **Ultra（仅本机运行面，冻结保留）**：目标 → 主管拆题与持续重规划 → 受限调查单元 → 证据合并 → 报告与核验 → 必要时定向回查 → 保存。支持查看、取消、来源与结果读取；用户看到的计划只读，内部计划随证据变化。该引擎依赖长驻进程与本地持久化，不上 serverless，也不再演进。

普通简报、众声和热榜已有原型继续保留。已保存研究报告随研究任务读取，不设独立简报库入口（见 [ADR-0009](decisions/0009-remove-brief-library.md)）。**资料库与全局搜索已移除**（依赖本机私人资料，无服务端 owner，见 [ADR-0008](decisions/0008-web-only-server-hosted-research.md)）。个人知识桥、持续研究、报告编辑与更多产品能力按未来独立需求评估，不进入当前任务清单。

**个人档案**（登录用户自身的创作 / 收藏 / 关注，经规则组装成视图）已确认设计，范围见 [ADR-0010](decisions/0010-personal-archive.md) 与[个人档案设计](../design/个人档案设计.md)。它数据来自登录用户自己的开放平台数据，**不是**已移除的资料库（后者依赖本机私人资料）；采集与组装分离，快照按用户隔离，组装层无模型调用。

## 身份与安全

- Access Secret 是开放平台调用方凭证，只在服务端或受控进程中使用。
- OAuth access token 只代表已授权用户，必须和 Access Secret 分开保存；没有授权用户时不得回退到凭证所属账号。
- 原型阶段默认使用单一服务端 Access Secret；OAuth 需在平台确认 `state`、PKCE、刷新和撤销协议后再产品化。
- 产品只交付网页端；桌面端凭证桥不再作为形态依据（见 [ADR-0008](decisions/0008-web-only-server-hosted-research.md)）。
- 用户数据、知识库内容和完整 API 响应按最小读取范围处理；来源 URL、作者和归属信息必须保留。

## 额度、缓存与失败

- 额度策略由产品层拥有，运行时使用 `/api/v1/quota` 的实时结果，不硬编码额度作为成败依据。
- 当前研究默认关闭自动重试，所有实际尝试计入任务预算。其他能力只有幂等 GET 可按明确策略有限退避；直答和上传等 POST 不自动重试。
- 当前研究只在同一任务内对规范化查询去重，不建跨任务缓存平台。未来私人资料缓存必须隔离身份。
- `AUTH_REQUIRED`、`AUTH_INVALID`、`RATE_LIMITED`、`QUOTA_EXHAUSTED`、`UPSTREAM_ERROR`、`MODEL_NOT_CONFIGURED` 和 `PROTOCOL_ERROR` 映射为稳定产品错误码。
- 接口失败、空结果和字段缺失是三种不同状态，不能用空列表掩盖鉴权或协议错误。

## 演进顺序

按[实施任务](../research/implementation-tasks.md)完成 R1 研究链路、R2 补查与证据质量、R3 生命周期收敛。完成后即结束当前开发范围；是否加入其他平台能力，根据实际需求另行决定。
