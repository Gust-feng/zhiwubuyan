# 开发维护规则

## 模块与命名

- 文件和函数命名使用稳定的领域词，例如 `content-search`、`knowledge-search`、`research-brief`；不要用接口路径或临时页面名称作为业务模块名。
- 第一层只暴露能力门面，不让上层依赖 HTTP 客户端、Header、原始响应大小写或 MCP 会话细节。
- 第二层以 Application command 作为唯一业务入口；Agent 工具、Workflow 步骤、UI 和路由都调用 command，不重复授权、预算和保存政策。
- 每个长期事实只有一个 owner：身份归 `auth`，额度归 `quota` 策略，证据归研究模块，持久化归本地存储模块。

## API 适配

- 所有请求使用官方 Base URL、Bearer Access Secret 和秒级 `X-Request-Timestamp`。
- Query 与 JSON 字段保留官方 PascalCase；内部类型可以使用项目自己的命名，但只在适配边界转换一次。
- 先检查 HTTP 可用性，再检查业务 `Code`；直答使用其 OpenAI 风格错误结构。
- 分页游标和 `NextOffset` 必须按官方类型传回，解析失败报协议错误，不静默截断。
- 只对幂等 GET 做有限重试；直答、上传和其他副作用 POST 不自动重试。
- 所有用户输入都经过 schema 校验。详情 ID 必须从列表结果取得并进行 path-safe 编码。

## Mastra、工作流与工具

- 框架按 ADR-0003，研究范围按 ADR-0005，运行方案按 [ADR-0006](decisions/0006-supervised-research-runtime.md)。不再以 A/B、预算曲线或多题 benchmark 作为架构前置。
- 一个顶层 Workflow、一个主管、受限并行调查单元。框架定义集中 src/agent，复用官方 Agent 工具循环、foreach/循环和 createTool，不自研执行引擎。
- 固定用户目标、权限与预算；主管通过一个命令更新动态计划。单元只提交来源、带引用 findings 和建议，不能改全局范围或递归启动 Agent。
- Mastra 保存阶段与活动执行，产品保存计划、证据关联与最终 outcome。源数据与完整工具结果不放进每个 Workflow 快照。
- 预算准入及预占在并行派发之前完成，所有单元共享全局额度；Agent.generate 的每个实际模型步骤都计量。未知消耗不返还，已知未用预留可释放。
- 每次来源、发现、计划和报告提交在事务内重验任务仍可写；取消终止所有活动单元，迟到回调不能写入。报告与 completed 同事务提交，重复请求和保存幂等。
- 核验可触发一次定向回查，回查结束必须重新核验；不能把未通过检查的草稿保存为正式报告。
- 只通过公开 API 访问框架快照；产品 schema v2 不兼容旧未发布开发数据时明确失败，显式重置，禁止启动时删除。重启只标记 interrupted，不自动恢复执行。
- 保留必要类型/构建与数据、预算、取消边界核对；不要求用户投入手工比较，不把未验证的研究效果写成事实。

## 凭证、缓存与数据

- Access Secret、OAuth App Key、OAuth token 只允许存在于服务端 Secret Store、环境变量或进程内存。
- 不把完整凭证写入日志、数据库、URL、前端响应、截图、测试快照或模型消息。
- 缓存键必须包含能力类型、规范化输入、身份范围和协议版本；用户数据与公共数据不能共用缓存。
- 文件上传只有用户明确指定单个文件并确认后才能执行；超时后先查询知识库状态，再决定是否重试。

## 变更与验证

- 修改公共命令、错误码、身份模型、数据格式、删除语义或状态机前先更新架构基线并记录 ADR。
- 小型文案、样式和纯类型变更默认不新增测试；涉及数据、权限、并发、恢复或上传时补最小核心场景测试。
- 提交前检查 `git diff --check`、类型检查和受影响模块构建；不要执行全量测试替代针对性验证。
- 生产运行时不得依赖全局安装的 CLI 子进程；CLI 只作为开发/运维入口，产品能力通过适配层直接调用官方 API。
