# ADR-0005：当前只交付深度研究

日期：2026-09-13 · 状态：accepted（按用户确认收敛开发范围；不是实现完成记录）。

> 运行策略已由 [ADR-0006](0006-supervised-research-runtime.md) 更新：采用主管与并行调查单元、动态计划和核验回查。本文的只做研究范围、保存/取消原则保留；固定计划、串行调查与旧轮数策略不再作为实施要求。
>
> 账号范围已由 [ADR-0007](0007-dual-surface-web-desktop.md) 更新：知乎 OAuth 登录与用户数据读取进入范围，仅限网页端。桌面端形态随后被 [ADR-0008](0008-web-only-server-hosted-research.md) 取代（产品只交付网页端，桌面端冻结），研究由服务端承接。

## 背景

上一版方案把研究链路与聊天、个人账号、桌面发布、成果版本和精细恢复同时列为交付要求。用户明确当前只做深度研究。需要保留研究质量与基本数据可靠性，移除尚未证明必要的产品基础设施。

## 决策

1. 继续采用 Mastra Agent + Workflows。一个独立 ResearchTask 对应一次 Workflow 执行；不依赖 Conversation、Space、Memory、模型配置管理页面或完整桌面接入。
2. 唯一主链路为：提交问题 → 自动规划 → 知乎公开检索 → 分析证据 → 有限补查 → 撰写与检查 → 保存报告。计划生成后直接执行；当前不提供计划编辑、确认启动、暂停、继续或恢复接口。
3. 知乎公开搜索为默认来源。创建时可明确允许现有全网搜索接口补证，默认关闭；收藏、创作、知识库、导入材料与旧报告复用均后置。来源能力目录不是本期功能清单。
4. 产品事实收敛为任务、来源快照和报告。计划、查询记录、分析与用量放入任务的有类型 JSON；不为每项分析中间产物建立表、repository 或公共 API。Mastra 仍是步骤、循环位置及执行快照的唯一 owner。
5. 当前研究模块拥有 ResearchReport，一项任务最多一份不可变报告。取消 ADR-0002/0004 中首版必须经 library/BriefRevision 保存的前置要求。现有普通简报不迁移、不改写；未来成果库只引用报告身份，若变更 owner 另写 ADR，不能复制出两个可写正文。
6. 任务保存产品最终结果 outcome 和结束时间，用于保护来源写入、取消与成果提交；不保存另一份可调度的 status/stage。报告与 completed outcome 在同一产品事务提交，提交成功就是产品成功，后续框架收尾失败不得撤销成果。
7. 一次只执行一个研究任务，不建排队服务。创建请求使用 requestId 去重，同 key 不同输入报冲突；重复保存返回同一报告。新任务在已有执行收尾前返回 TASK_BUSY。
8. 取消先在产品事务中关闭写入和调用准入，再通过官方取消信号停止模型与知乎请求。取消与报告保存竞争时以先提交的产品事务为准。迟到返回不能新增来源或报告。
9. 进程重启只读取结果，并把没有产品终态的旧任务标记 interrupted；不调用 resume/restart、不重发外部请求。已完成报告仍可读。用户需要再次研究时创建新任务，使用新 requestId。
10. HTTP 只提供创建、列表、查看、取消、来源与报告读取，进度轮询。Markdown 导出由同一报告确定性渲染，不引入导出任务系统、SSE 重放或事件数据库。
11. 复用成熟模型接入、本地 libSQL/SQLite 和现有 HTTP adapter。模型与知乎凭证只从后端配置取得，本期不开发账号体系、凭证原生桥或设置平台。产品库与框架库分开，禁止访问框架内部表。
12. 继续保护真实证据、引用可追溯、有限调用、超时、取消和原子保存。这些是研究交付的必要条件；跨任务知识库、任意步骤恢复、多 Agent、监测、备份和安装包不属于本期验收。

## 补查策略修订

用户进一步明确深度研究需要更宽松的调查空间。取消固定两轮补查的限制，采用可配置的总轮数、搜索调用、模型调用和时长预算；具体默认值由[开发方案第 7 节](../../deep-research-development-plan.md#7-预算超时与失败)维护，在创建任务时冻结。

研究按关键问题的证据缺口继续，证据充分可提前收尾；连续两轮补查没有有效进展才触发低收益停止。单轮失败或没有新资料时，允许针对同一缺口尝试不同查询方向。没有合法的新查询、预算耗尽或来源不可用仍可直接停止。上限不要求跑满，扩大调查预算不增加 Agent 层级、数据表或公共控制接口。

- [开发方案](../../deep-research-development-plan.md)：研究算法、数据和故障规则。
- [后端 API](../../backend-api.md)：当前唯一 HTTP 协议。
- [实施任务](../../research/implementation-tasks.md)：三个研究交付阶段。

较早的平台设计保留为[历史参考](../../research/deferred/README.md)，不得按旧清单开发。当前文档不要求删除已存在的其他功能、依赖或并行前端改动。

## 取舍

首版能独立验证“多轮研究是否比单次检索产生更有依据的结论”。代价是中断任务不能继续、报告不能原地编辑、个人资料暂不参与。后续需求出现时再增加对应能力，先以真实运行记录判断是否值得承担复杂度。
