# ADR-0001：本地后端边界与持久化

> 当前适用范围由 [ADR-0005](0005-deep-research-mvp-scope.md) 更新。本文中的聊天、桌面进程、配置与备份交付要求已后置；当前只实现研究需要的本地后端。 下文保留决策历史，不能按其中被覆盖的清单开发。

日期：2026-09-13 · 状态：实施设计；底层框架已按 [ADR-0003](0003-mastra-foundation.md) 确定，运行组合尚待验证。

## 背景

产品需要同时提供连续对话和基于知乎证据的研究流程。现有公开内容与用户数据 adapter、内存研究会话和前端原型可继续利用；持久化 Agent、研究工作流和桌面后端生命周期尚待实现。

已确认 Windows、本地单用户、数据与任务保存在本机、模型可以使用云端 API。后端通过稳定契约独立开发，不依赖前端组件。

## 决策

### 1. 独立 Node 后端，由 Electron 监督

随安装包携带固定 Node 24 LTS，桌面通过隐藏子进程启动，后端提供同源 loopback HTTP/SSE。CLI 连接同一应用服务；发布不依赖全局 CLI、开发服务器或用户安装的 Node。

相比直接运行在 Electron 主进程，该方式隔离业务故障并固定后端运行环境；代价是额外包体与进程监督。相比 utilityProcess，它减少对 Electron 内置 Node 的依赖。Windows 数据库与随包 Node 组合在 M0 验证。

同一数据目录先取得 OS 独占命名管道再打开存储；Electron 单实例锁只负责窗口。HTTP 另校验本地会话、Host 和 Origin。

### 2. Mastra 是执行基础，应用命令拥有业务政策

使用官方 Agent、Workflows、工具、Memory 和存储接口。框架定义集中在 `src/agent`；应用命令不导入框架内部类型。工具和工作流步骤调用同一取证、授权、预算及保存命令。

聊天 Run 管理一次用户对话任务；研究 ResearchTask 由独立 Workflow 执行。两者共享基础资源限额和产品命令，但研究不占用聊天队列，也不共享活动聊天上下文。

### 3. 产品库与框架库分工

| 数据 | 唯一写入边界 |
| --- | --- |
| 组织、研究目标、计划版本、来源、预算、授权、成果、操作回执 | 产品应用命令与 SQLite repository |
| Conversation 元数据、聊天 Run 意图与生命周期、研究派发/控制意图和框架引用 | 相应产品应用命令 |
| 消息与工具结果历史 | Mastra Memory 的公开接口 |
| 工作流步骤状态、执行快照和恢复位置 | Mastra Workflow / 官方存储接口 |
| 会话预览、研究执行状态、阶段进度 | 查询投影；不得独立修改 |

产品库采用 `better-sqlite3` 的窄 adapter，框架库采用 `@mastra/libsql` 的本地文件模式，分别保存为 `product.sqlite` 与 `runtime.sqlite`。物理分库明确迁移与写入责任，不直接操作框架内部表。

Conversation 保留当前与历史 Memory thread 的关联；resourceId 绑定研究身份，threadId 区分上下文周期。重置上下文创建新 thread，保留旧历史；默认关闭跨会话语义召回、自动用户画像和后台观察记忆。

### 4. 跨存储提交和恢复

两类数据库不共享原子事务。提交简报在产品事务内完成版本检查、引用检查、写入和操作回执；框架步骤得到稳定结果引用后再完成 checkpoint。恢复先查回执，避免保存成功后重复生成成果。

聊天执行中断后保留可读取历史，Run 标记 interrupted，用户继续时只使用可确认的上下文。研究根据持久化框架快照、已提交步骤回执和控制意图恢复；不能从聊天文本推断进度。

正常 suspend/resume 与崩溃恢复分开验证。恢复同一步骤可能重新执行代码，必须识别未确认的模型请求与外部操作；不在应用重启时自动消耗新额度。

### 5. 公共契约与能力适配

共享契约使用 Zod，位于 `src/contracts`。前端、mock 与后端共用 schema，运行和流式事件使用产品 ID，框架内部对象不成为 UI 协议。

运行中引导、Skills、上下文处理和更多 provider 以锁定版本的实际能力为准。核心取消、工具往返与持久化必须通过验证；未验证扩展明确返回 capability 状态，不仿造旧框架方法。

真实模式禁止自动回退示例数据；snapshot 为可恢复状态，SSE 提供有界增量与 reset。

## 数据与生命周期

- 新产品 schema 随实现建立版本；不为尚未实现的框架设计编写数据迁移，也不静默清空现有数据。
- 后续产品 schema 追加迁移，框架升级记录框架包与数据兼容条件。恢复前检查备份版本。
- 停机一致性备份包含两类数据库和导入文件；关闭写入者并完成数据库收尾后复制，凭证不进入普通备份。
- 会话归档停止其聊天 Run，不隐式取消独立研究任务；分组归档需通过明确应用命令协调其活动任务。
- 所有权限、预算、删除、版本和幂等规则由同一应用入口执行，前端和框架 adapter 不复制。

## 验证与落地

M0 验证 Windows / Node / Mastra / 数据库组合、一次真实工具调用、Memory 重开和 Workflow 暂停恢复。后续保护取消、预算、旧尝试失效、版本冲突、引用与成果保存等核心不变量。

详细实施以 [后端设计](../../backend-design.md) 和 [接口与前端对接](../../backend-api.md) 为准，研究执行见 [ADR-0002](0002-deep-research-workflow.md)。
