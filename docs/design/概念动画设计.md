# 成象（概念动画）设计

日期：2026-09-14 · 状态：**已实施**（契约、取料、模型适配、应用命令、存储、两运行面路由与工作台板块均完成；离线验证通过，真实模型端到端生成与浏览器实测已走通）。

「成象」是工作台的一个顶层板块：用户输入一个概念或一句话，产品先取一批**知乎检索摘要**作为资料，再让模型产出一份可离线打开、分步讲解的单文件 HTML 动画；结果可播放、可下载、留档，历史可见。

名字取自「在天成象」：概念成形，可见为象。板块名用「成象」，后端沿用 `concept-animation` 模块名——与「深度研究 / 视图 id `ask` / 后端 `research-*`」的既有命名先例一致，不是两套名字。

## 1. 定位与边界

| 项 | 结论 |
|---|---|
| 输入 | `topic`（概念或一句话，1–200 字）+ 可选 `instruction` + `useMaterial`（默认开） |
| 取料 | 生成前用 `topic` 检索知乎，取前 6 条摘要注入提示词；失败降级为凭模型知识生成 |
| 产物 | 自包含单文件 HTML（内联 CSS/JS/SVG，无外链、不联网） |
| 模型 | OpenAI 兼容 `chat/completions`，BYOK；凭证只经内存 |
| 落库 | 生成成功即落库（本机文件 / 网页 KV），历史列表可读、可删 |
| 成本 | 一次生成 = 1 次检索 + 1–2 次模型调用（校验未过时整份重生成一次） |

明确不做：动画内部结构的解析与二次编辑、逐帧控制、导出视频、多轮对话式微调。动画的讲解质量与动效风格由系统提示词约束，产品侧不维护第二套分镜模型。

沿用既有约定：契约用 Zod 且类型从 schema 推导；应用命令是唯一业务入口；适配层不依赖 UI/路由；错误统一为 `ProductError`；取料与缓存放在命令之外，命令本身可离线测试。

## 3. 取料链路（本功能的质量增量）

模型凭自身知识讲抽象概念容易空泛甚至出错；知乎语料能校正事实、提供常见讲解角度。取料是「成象」相对纯生成的关键增量。

- **取什么**：`runtime.content.searchZhihu(topic, count 8)`，按 URL 去重后取前 6 条。
- **注入哪些字段**：只注入 `title` + `summary`（截断至 600 字）+ `authorName`。
- **不注入**：`url`（避免模型编造引用）、头像/认证图标地址、内部标识（contentId / questionId / thumbnailUrl）。
- **只进提示词，不上界面的**：参考资料是给模型校准事实用的输入，不在动画页面上罗列展示；界面不出现「参考知乎资料」开关或来源清单。
- **提示词里的形态**：编号参考资料清单 + 使用规则（「这是摘要不是原文，用于校准事实与例子，不要整段搬进画面，不要虚构作者/数字/出处」）。

三条边界（沿用产品红线）：

1. **摘要不是全文**——字段用 `summary`，不新增 `content`/`fullText`，任何地方不说成原文。
2. **不许编造引用**——参考资料是视角，不是可照抄的原文；引用校验不接受虚构来源。
3. **取料失败不阻断**——限流/额度耗尽/未配凭证/无结果时降级为凭模型知识生成，标 `materialStatus: unavailable`，不假装有资料。

取料固定开启：界面上不提供开关，每次生成都会尝试取料，失败则如实降级。

成本控制：一次生成只检索一次；同主题 15 分钟缓存 + 单飞（进程内有界缓存），保护按账号汇总的 `zhihu_search` 额度（5000/天，**所有部署共享**）。

## 4. 生成流程

1. **取料**：`useMaterial` 且注入了 provider 时 `load(topic)`；否则 `skipped`。
2. **构建提示词**：`buildConceptAnimationPrompt` 组装系统提示词，写入主题、额外要求、参考资料与（修正轮的）问题清单。
3. **调用模型**：一次 `chat/completions`，`temperature` 默认 0.8，可选 `max_tokens` 与中止信号。
4. **抽取 HTML**：`extractHtmlDocument` 优先取 Markdown 围栏内容，其次取整段 `<!DOCTYPE html>`…`</html>`。
5. **安全加固**：`hardenDocument` 移除一切外部引用（外链 `<script src>`、`<link>`、`<base>`、`<iframe>/<object>/<embed>`、外链 `<img>`），并清空 `javascript:` 伪协议；返回被移除数量。
6. **校验产物**：`validateDocument` 检查文档结构、「是否真有动画」、「是否仍自包含」，以及「骨架是否被正确使用」（`{{...}}` 占位符是否替换、分镜数是否 ≥ 3）。
7. **至多一次修正**：校验未过时把问题清单回填提示词，让模型**整份重做**一次；再不过则如实失败。
8. **落库**：成功则由路由保存记录（`AnimationRecord`），返回结果与记录 id。

修正只重做一次是刻意的：这类生成本就慢，无限重试会放大延迟与成本；一次足够覆盖「返回格式跑偏」这类高频问题。

## 5. 提示词要点

提示词是本能力的核心，独立放在 `application/concept-animation-prompt.ts`，改提示词不动代码。面向「模型能力一般」的现实做过针对性升级，分十节：

- **输出契约**：只输出 HTML；完全自包含；只用原生能力；禁 `eval`/`new Function`/动态 `import`；不读写存储、不访问 `window.parent`。
- **必须使用的骨架**：给一份**完整可用的 HTML 骨架**——底部控制台、旁白区、分步控制器全写好，模型只填 `<main>` 里的图示和 `steps` 数组，并替换 `{{...}}` 占位符。这是升级的核心：不再要求模型从零发明控制器。
- **先规划内容 → 每一步怎么写 → 常用动画配方 → 节奏 → 旁白 → 交付前自查 → 绝对禁止**：给出 5–7 步讲解线路、`async enter` + `await tween` 用法、可照抄的动效片段（对比/柱状图/SVG 描边/高亮等）、最小时间约束、看山口吻与自查清单。
- **参考资料**：有资料时给编号清单与使用规则；无资料时明确「本次未接入外部资料，不要编造具体来源」。

设计原则：**提示词承担质量，代码只承担底线**。动效好坏、讲得清不清楚交给提示词；代码只管抽取、安全加固、结构校验这类不能靠「提示」保证的硬判断。

## 6. 安全加固的取舍

模型产出的 HTML 会在浏览器里执行，因此加固是必须的：

- **移除而非报错**：外链移除后，只要动画本身是内联的，产物依然可用，比直接判失败对用户更友好。
- **只清属性不删标签**：`javascript:` 伪协议清空属性值，避免破坏标签结构。
- **外链判定只看标签属性**：用 `/<[^>]+(?:src|href)\s*=\s*["'](?:\/\/|https?:)/i`，不看脚本字符串或注释，避免把文案里的 URL 误判成外链而误伤内容。校验与加固共用这一口径。

前端播放时再用 `<iframe sandbox="allow-scripts">` 二次隔离：**不给 `allow-same-origin`**，产物拿不到同源权限，读不到父页面、存储与 cookie。提示词要求它不访问 `window.parent`，沙箱是兜底。

## 7. 存储与隔离

- **端口**：`application/animation-records.ts` 声明 `AnimationRecordStore`（list/get/save/remove），实现按运行面选择。
- **本机**：`storage/animation-store.ts` 的 `createFileAnimationStore`——每个 scope 一个子目录，`index.json` 存摘要列表、每条记录单独 `<id>.json`；列表不读回全部正文。
- **网页**：`createSharedCacheAnimationStore`——`imagery:v1:<scope>:index` 存摘要数组、`imagery:v1:<scope>:record:<id>` 存整条；远端保留窗口 180 天。
- **隔离**：记录按 scope 分离。本机固定 `local`；网页端用 `/user` 的 `hash_id`，拿不到时退回会话内临时键——与个人档案同一策略，绝不把不同用户混进同一 scope。
- **容量**：单 scope 保留最近 60 条，超出按时间淘汰并清理孤立记录文件。

## 8. 配置

模型配置优先读 `ANIMATION_MODEL_*`，未配置时回退深度研究的 `MODEL_*`：

| 变量 | 说明 |
|---|---|
| `ANIMATION_MODEL_API_KEY` / `MODEL_API_KEY` | 必填 |
| `ANIMATION_MODEL_BASE_URL` / `MODEL_API_BASE_URL` | 必填，OpenAI 兼容端点 |
| `ANIMATION_MODEL_ID` / `MODEL_PROFILE_MODEL_ID` | 必填 |
| `ANIMATION_MODEL_PROVIDER` / `MODEL_PROVIDER` | 可选，展示用标签 |
| `ANIMATION_MODEL_TEMPERATURE` | 可选，默认 0.8 |
| `ANIMATION_MODEL_MAX_TOKENS` | 可选 |
| `ANIMATION_MODEL_TIMEOUT_MS` | 可选；网页端强制不超过 50s（函数时长余量） |

端点归一：基址可带 `/v1`，也可直接写到 `/chat/completions`；Gemini 只给站点根域名时自动补 `/v1beta/openai`。

取料依赖部署方的 `ZHIHU_ACCESS_SECRET`（服务端持有）；未配置时取料降级为 `unavailable`，生成照常。

## 9. 运行面接线

- **本机（long-running）**：`local-server.ts` 注册共享路由，scope=`local`，capabilities 加 `concept_animation`；取料 provider 进程内单例（缓存跨请求复用）；超时默认 300s。
- **网页（Serverless）**：`web-api.ts` 装配共享路由与共享缓存存储；`zhihu-api.ts` 负责登录门槛（生成消耗搜索与模型两类额度，未登录拒绝）、限流（scope `concept-animation`）、以及把会话派生的用户 scope 交给路由。函数时长上限 60s，因此生成超时压到 50s 以内，超时按 504 返回。capabilities 同样加 `concept_animation`，前端据此启用入口。

## 10. 使用与验证

- 本机实时生成：`pnpm concept-animation "冒泡排序" [--instruction "…"] [--json]`，产物写到 `output/concept-animation/<slug>.html`。
- HTTP：
  - `POST /api/concept-animation`，体 `{ topic, instruction?, useMaterial? }` → `{ ok, data, recordId }`；未配模型返回 `503 ANIMATION_MODEL_NOT_CONFIGURED`。
  - `GET /api/concept-animations?limit&offset` → 历史列表（不含 html）。
  - `GET /api/concept-animations/:id` → 单条完整记录；`DELETE` 删除。
- 离线验证：`pnpm verify:concept-animation`，用假模型与假检索覆盖抽取、加固、校验、一次修正、取料降级、缓存单飞、存储 scope 隔离与错误映射，不触网、不消耗额度。

## 11. 实测与已知限制

**实测记录**：`gemini-3.5-flash-lite` 走 HTTP 产品路径生成「复利效应」成功——HTTP 200、`materialStatus: used`、6 条真实知乎参考资料（作为提示词输入，不上界面）、12KB 自包含 HTML、落库并可列表/详情读回。入口与结果态（图标换场、标题、输入卡、沙箱 iframe 播放、控制台、历史列表）均已走通。

**模型接入事实**（对本能力选型有直接影响）：

- Gemini 的 OpenAI 兼容入口在 `/v1beta/openai` 下，厂商只给站点根域名时适配层会自动补全。
- Gemini 免费层 key 上，完整版 flash（3.8/3.7/flash-latest）在长输出时稳定 503，只有 `gemini-3.5-flash-lite`/`3.1-flash-lite` 稳定可用；`gemini-2.5-pro` 免费额度为 0。
- OpenRouter 的 `:free` 模型上游限流严重，对长输出几乎稳定失败，不适合本能力。

**已知限制**：

- **语料只提升「讲什么」，不改善动画表现**：分镜设计、动效节奏、视觉呈现仍取决于模型能力。
- **模型拿到大段摘要易把画面堆成文字墙**：提示词已明确约束，仍需按主题实测调优。
- **输入 token 约翻倍**：一次生成带 6 条摘要，延迟与费用相应上升；网页端受 60s 函数时长约束。
- **两侧存储不互通**：本机落文件、网页落 KV，与项目「无服务端持久目录」的现状一致。
