# 深度研究界面设计（v2）

日期：2026-09-13 · v2 对齐已实现的 ADR-0006 研究契约与 ADR-0007 四档分档。v1 确认的"主区研究卡片 + 右侧研究活动面板"布局、冷白灰/墨水蓝主题与工作台导航保持不变；本文替换状态矩阵、数据映射与档位入口设计。桌面端锁定与下载引导（v2 原文）已由 [ADR-0008](../architecture/decisions/0008-web-only-server-hosted-research.md) 撤销：产品只交付网页端，研究改由服务端承接，接入完成前入口显示未接通说明。

数据来源：`GET /api/research-tasks/{id}` 的 TaskDetail（共享 Zod：`src/contracts/research.ts`）。UI 不猜进度、不按定时器推演状态；一切进度表达来自 status/stage/queries/usage 的真实投影。

## 1. 入口与档位

深度研究入口 = 问题输入 + 档位选择 + 全网补证开关。

```
┌────────────────────────────────────────────────────────────┐
│  深度研究                                                    │
│  ┌──────────────────────────────────────────────────────┐  │
│  │ 输入你想研究的问题…                                    │  │
│  │                                                      │  │
│  └──────────────────────────────────────────────────────┘  │
│  档位：  ◉ Pro   直答检索增强 · 约 30 秒                  │
│          ○ Ultra 自研多单元研究 · 深度报告                  │
│          （服务端研究引擎接入前，提交区显示未接通说明）        │
│  ☐ 允许全网补证（仅 Ultra 生效；默认关闭）                    │
│                                    [ 开始研究 ]             │
└────────────────────────────────────────────────────────────┘
```

- **tier 必选**，入口初始值取「设置 → 研究偏好 → 默认研究深度」，未设置时为 Pro；单次研究可在入口覆盖。全网补证开关同理取「默认全网补证」，未设置时为关闭。
- Ultra 由服务端承接：服务端未声明研究能力时，提交区显示未接通说明并禁用提交（前端按 `/api/status` 的能力集判定，不发注定失败的请求）；声明后可提交，202 进入研究主视图。
- Pro 提交后为**同步等待**（实测约 30 秒）：按钮进入加载态，完成后直接进入"快答视图"（§4）。
- Ultra 提交后 202，进入"研究主视图"（§2），轮询 1–2 秒。

## 2. Ultra 研究主视图（布局沿用 v1）

```
┌──────────────────────────────┬───────────────────────────┐
│ 主区（研究卡片）               │ 活动面板 340–380px         │
│                              │ [研究活动] [来源]           │
│ 问题：家用 NAS 的用途、维护…    │ ── 研究活动 ──             │
│ 状态徽标：研究中 · 取证        │ ▸ 规划  v1 计划已生成       │
│                              │ ▸ unit-a1 检索 zhihu        │
│ 计划 v3（可折叠）              │   "家用NAS 维护 经验"       │
│  ✓ q1 用途场景     [充分]      │   ✓ 命中 5 · 来源 4        │
│  ✓ q2 维护负担     [部分]      │ ▸ unit-a2 检索 zhihu …     │
│  ◐ q3 失败经验     [冲突]      │ ── 用量 ──                 │
│  ○ q4 长期对比     [未回答·已关闭]│ 搜索 96/160 推理 107/200  │
│  + 主管新增：q5 品牌支持年限    │ 来源 158/800 · 已用 12 分钟 │
│                              │           [ 停止研究 ]     │
│ 一句当前活动：正在核查RAID误区… │                           │
└──────────────────────────────┴───────────────────────────┘
```

### 2.1 主区元素 ↔ 数据映射

| UI 元素 | 数据来源（TaskDetail） | 规则 |
| --- | --- | --- |
| 问题 | `question` | 原样展示 |
| 状态徽标 | `status` + `stage` 投影 | stage 文案映射：planning=规划中 / researching=取证 / writing=撰写 / reviewing=核验 / repairing=定向回查 / saving=保存；stage=null 时仅显示 status |
| 计划卡 | `plan` | 标题"计划 v{version}"；子问题行：`id`+`text`+优先级徽标（high=深色）+关闭态（closedReason 非 null 显示"已关闭·不再相关/来源饱和"的灰化行，保留历史）|
| 覆盖徽标 | `analysis.answers[].coverage` | supported=充分 / partial=部分 / contested=冲突 / unanswered=未回答；无 analysis 时计划行无徽标 |
| 覆盖详情（展开行） | 对应 answer 的 `text` + `gaps` | 折叠在计划行下，点击展开 |
| 一句当前活动 | `stage` + 最新 queries | 文案由前端按 stage 生成（"正在取证：n 个单元并行"），不展示模型思维链 |
| 发现数 | `findings.length` | 作为次要统计，不作进度承诺 |
| 结束原因/完整度 | 报告的 `stopReason`/`completeness` | 完成后展示在报告头 |

### 2.2 活动面板

- **研究活动**：`queries[]` 按请求时间正序的时间线。每条：unitId（短标）+ channel 徽标（知乎/全网）+ text + status（pending=转动 / succeeded=✓ / failed=✗）+ 命中来源数（`sourceIds.length`）+ 剔除数（discardedCount>0 时）。pending 表示"上游结果未确认"，转圈而非假完成。
- **来源**：`GET /sources` 列表。每条：标题、作者展示名、内容类型（Answer/Article）、时间语义（sourceTime + timeKind，"发布/更新"措辞）、互动数；点击进详情抽屉：完整摘要、原始 URL（外链按钮）、identity、textHash 不展示给用户。contentExtent 恒为 summary——详情页固定注明"摘要，非全文"。
- **用量**：`usage` 对照 `limits` 逐项显示"已用/上限"（搜索请求、模型推理、来源快照）与已用时长；不显示百分比进度条（预算≠进度）。
- **停止研究**：任何非终态可点 → 202 cancelling（按钮变"正在停止…"）→ 终态后恢复；已保存来源保留可见。

### 2.3 终态视图

- **completed**：报告成为主阅读对象——标题、完整度徽标（充分/部分）、结束原因、四部分正文（conclusion/evidence/disagreements/gaps 各自小节，gaps 为列表）、limitations 块、来源引用编号（按首次出现排序，点击定位来源详情抽屉）；操作：导出 Markdown（`report.md`）、基于同一问题新建研究。
- **failed**：保留问题/计划/来源/查询，error.code + 脱敏 message，附"新建研究"引导。
- **cancelled**：材料保留 + "已取消"说明。
- **interrupted**："上次进程退出，本任务已中止（不自动继续）"；材料可查，新建研究需新 requestId。
- cancelling 期间保留最后 stage 徽标 + 按钮禁用态。

## 3. Pro 研究报告视图（ADR-0014）

Pro 与 Ultra 共用同一套工作区壳，不再各写一套版式：

```
┌────────────────────────────────────────────┬──────────────────────┐
│ [新研究]                            [面板] │ RESEARCH NOTES       │
│                                            │ 研究要点 │活动│来源  │
│ RESEARCH REPORT              ✓ 研究已完成  │ ──────────────────── │
│ 报告标题（编排目标）                        │ 01 …        已有依据  │
│ 从公开讨论出发，保留结论成立的条件。         │ 02 …        部分依据  │
│ 知乎深度研究 · Pro · N 个来源 · 正在整理报告 │ 03 …        尚未回答  │
│                                            │                      │
│ ## 摘要  / ## 背景与范围                    │                      │
│ ## 主体分析（### 每个子问题一节）            │                      │
│ ## 结论与建议 / ## 分歧与争议 / ## 缺口与限制 │                      │
│ 正文句末 [n] 引用，点击跳到来源              │                      │
│                                            │                      │
│ 每个判断，都有来路。          查看 N 个来源 →│ N 个来源             │
└────────────────────────────────────────────┴──────────────────────┘
```

- **主栏报告**：Pro 为本次生成的报告（随事件流实时渲染），Ultra 为已保存报告；两者版式一致（eyebrow、标题、元信息、正文、底部复制/下载）。
- **报告正文**：固定六节 Markdown（摘要 / 背景与范围 / 主体分析 / 结论与建议 / 分歧与争议 / 缺口与限制）；主体分析按子问题各起三级标题。引用为 `[编号](链接)`，点击定位到右侧来源，编号只来自本次收集的资料。
- **右侧详情面板**：三个页签——「研究要点」（子问题与取证状态，仅 Pro 有）、「研究活动」（拆题 → 每轮取证 → 成稿）、「来源」（列表 + 点开看摘要与原文链接）。
- **阶段说明由真实事件驱动**：拆题未回 → "正在拆解问题"；子问题就绪 → "正在按子问题查找资料"；覆盖判断后 → "正在检索取证 / 正在整理报告"。不按时长推演进度。
- 与 Ultra 报告**语义区分**：Pro 页脚如实标注"基于检索摘要的多轮编排，未做证据级核验"；来源计数是检索摘要，不是已保存证据快照。
- 失败：任务 error 码直出（如 QUOTA_EXHAUSTED），提示重试或新建研究。

## 4. 状态矩阵（替换 v1）

| status | stage | 主区 | 动作 |
| --- | --- | --- | --- |
| starting | null | 问题 + "正在启动" | 无 |
| running | planning/researching/… | 计划 + 活动面板（§2） | 停止研究 |
| cancelling | 最后 stage | 材料保留 + "正在停止" | 禁用停止 |
| completed | null | 报告（Ultra）/ 快答（Pro） | 导出、新建 |
| failed | null | 材料 + 错误 | 新建研究 |
| cancelled | null | 材料保留 + 已取消 | 新建研究 |
| interrupted | null | 材料保留 + 已中止说明 | 新建研究（新 requestId） |

## 5. 原型升级清单（确认后实施）

现有 `features/deep-research/` 需要的对接改动，均为投影层与视图模型扩展，不改布局骨架：

1. `research-view-model.ts`：场景扩展 starting/cancelling/interrupted + stage；新增 tier、plan.version/priority/closedReason、coverage、usage/limits、answer（Pro）、limitations/gaps/disagreements。
2. `research-projection.ts`：从 TaskDetail 真实投影替换 fixture 形状；fixture 场景改用契约示例数据（`docs/research/contract-examples.md`）。
3. 工作区组件：计划卡 v2（版本、徽标、关闭行、覆盖展开）、用量块、Pro 快答视图、报告 gaps/disagreements/limitations 小节。
4. 轮询接线：`use-deep-research.ts` 改为真实 HTTP（本地后端），1–2 秒轮询，终态停止。
5. 首页问答模式（fast/thinking）不在本轮范围，后续作为独立入口接入同一快答视图。

- **报告正文**：固定六节 Markdown（摘要 / 背景与范围 / 主体分析 / 结论与建议 / 分歧与争议 / 缺口与限制）；主体分析按子问题各起三级标题。引用为 `[编号](链接)`，点击定位到右侧来源，编号只来自本次收集的资料。
- **右侧详情面板**：三个页签——「研究要点」（子问题与取证状态，仅 Pro 有）、「研究活动」（拆题 → 每轮取证 → 成稿）、「来源」（列表 + 点开看摘要与原文链接）。
- **阶段说明由真实事件驱动**：拆题未回 → "正在拆解问题"；子问题就绪 → "正在按子问题查找资料"；覆盖判断后 → "正在检索取证 / 正在整理报告"。不按时长推演进度。
- 与 Ultra 报告**语义区分**：Pro 页脚如实标注"基于检索摘要的多轮编排，未做证据级核验"；来源计数是检索摘要，不是已保存证据快照。
- 失败：任务 error 码直出（如 QUOTA_EXHAUSTED），提示重试或新建研究。
