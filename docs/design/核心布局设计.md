# 工作台核心布局设计

更新：2026-09-13。本文是当前工作台的信息架构、页面职责和布局规则的维护入口；实现目标为 `src/workbench`。

已确定：首页以知乎内容为主，只承载内容流与一次快速问答，研究入口与进展留在深度研究板块，不在首页重复出现。各功能板块保持独立职责与入口，新增板块不要求向首页增加面板。本文不代表所有接口联调或 Mastra 运行验证已完成。

术语见[理念体系](理念体系.md#6-术语系统)，业务与存储边界见[架构基线](../architecture/架构基线.md)，HTTP 契约见[接口与前端对接](../backend-api.md)。本文件不另建数据模型、研究状态机或主题令牌体系。

深度研究的任务内界面见[深度研究界面设计](深度研究界面设计.md)：主区呈现问题、计划与报告，右侧展开研究活动和来源。前端原型与后端并行推进，当前使用明确标识的示例材料，不代表真实研究已经接通。

## 1. 优化目标

首页避免把进行中、已完成与空状态排成等权面板，也不展开完整研究列表，不在首页重复承载研究入口与进展。首页专注内容浏览，研究留在自己板块的入口。

新的默认阅读顺序是：浏览具体内容 → 阅读原文或摘要 → 有明确意图时进入研究。研究在任务内完成，结果随任务沉淀；资料另有自己的工作区。

每个页面先回答一个主要问题，保留完成该任务的必要能力。板块独立指页面与业务职责清晰；公共导航、内容查询、阅读组件和对象引用可以共享。

## 2. 板块职责

| 板块 | 用户来这里做什么 | 默认工作区 | 边界 |
| --- | --- | --- | --- |
| 首页 | 浏览知乎内容，想看更多说法时转众声 | 热榜种子与主题检索的内容流；可发起一次直答快答 | 不承载研究入口、研究状态或成果；研究在深度研究板块，完整过程与资料目录留在所属板块 |
| 我的知乎 | 查看自己的笔记与知乎个人内容 | 登录门禁后的目录与内容列表 | 只展示我的笔记、我的创作、我的收藏与关注的人；不承载账号连接状态和对话 |
| 提问 · 研究 | 提出问题、推进已有研究 | 新建入口与研究列表；进入任务后显示计划、来源和必要进度 | 聊天 Run 与 ResearchTask 的生命周期分别由既有应用入口管理 |
| 众声 | 看一个议题下大家有哪些不同说法 | 议题输入 + 说法簇与落点条 | 只呈现检索范围内的说法与来路，不下结论、不编造热度；落点是加分项而非前提 |
| 成象 | 把一个概念变成看得见的讲解动画 | 概念输入 + 单文件动画播放器与历史 | 先取知乎检索摘要作参考资料，再产出自包含单文件 HTML；摘要不等于原文，动画质量受模型能力约束，不承诺讲解正确性 |

公共讨论只通过首页热榜进入，个人沉淀只通过“我的知乎”进入：同一来源不在两处重复铺开，也不为状态分类反复列出同一对象。

### 导航组织

稳定功能入口为：首页、我的知乎、深度研究、众声、成象；侧栏底部只放外观切换（浅色 / 深色 / 跟随系统），不设设置面板。“我的知乎”紧随首页；未登录时点击该入口直接打开登录弹窗，不加载个人数据，授权完成后返回该页面。网页端除热榜外都需要登录知乎账号，未登录进入“我的知乎”“众声”“成象”同样打开登录弹窗（不再各做一套门禁卡片）；深度研究与成象由服务端承接，服务端接入完成前入口给出未接通说明，研究报告在任务内直接打开、成象动画在板块内播放。深度研究、众声与成象的入口共用同一套版式与常驻外壳，切换时图标在同一格中心交替、各格内容就地换掉，不做整页重建。新增板块按用户任务放入合适位置；侧栏顶部的账号区是唯一的账号入口，其余部分只承载导航，不放正文、完整任务队列或大面积统计。曾经独立存在的“发现”入口已取消：它的公共讨论归首页热榜，个人面归“我的知乎”，检索条件归深度研究入口，不再单列一个聚合页。

“我的知乎”采用目录与内容列表的双栏形态。目录按“我的笔记、我的创作、我的收藏、关注的人”四个稳定维度组织，右侧只展示当前维度的条目；不增加对话目录，也不在页面内重复展示账号连接、令牌有效期或配置提醒。登录不可用或失败属于登录弹窗的错误状态，不伪装成空内容。

开发模式允许通过 `ZHIHU_DEV_USER_DATA=1` 使用当前项目的 ACS 作为调用方数据源，预览个人创作、收藏和关注内容；该开关只由 `pnpm dev` / `pnpm dev:api` 注入，本地生产启动与网页端不启用，不改变 OAuth 用户数据边界。

侧栏顶部是账号区，只呈现当前知乎账号的一行身份，不再放产品标志与品牌文案，也不写登录环境之类的状态说明。头像位常驻：已登录显示真实头像（取不到时用昵称首字），未登录显示默认人形头像；旁边只放昵称，未登录时是“登录知乎”。已登录点击展开只有“我的知乎”和“退出登录”的小菜单；未登录点击整行打开登录界面，授权完成后回到用户离开的视图。本地开发预览使用调用方身份读取个人数据，并非真实知乎登录，同样按“登录知乎”呈现，不新增预览文案。中部由导航自然伸展，底部外观入口保持固定。导航与外观入口之间可以放置一个“研究伙伴”入口：使用单个刘看山角色、简短提问和明确的“开始研究”动作承接留白，点击进入提问与研究页；该入口不展示虚构任务、统计或研究状态。

登录界面只有一份实现：左侧看山场景、右侧“知无不言”与“好奇心，带我们去更大的世界”，主线动作是“使用知乎继续”。网页端把它放进应用内弹窗，侧栏账号区、首页直答与检索、众声与我的知乎都用这同一个弹窗。**登录尚未接通时入口依然可点**：弹窗禁用继续按钮，并列出缺少的环境变量与待登记的回调地址，而不是做成点了没反应的死按钮。（桌面端冻结前由主进程开一个同版式的独立登录窗口，见 [ADR-0008](../architecture/decisions/0008-web-only-server-hosted-research.md)。）

侧栏不再使用跨越顶部或底部的大面积线稿、插画背景与为装饰预留的空白。角色只作为小面积、功能性的项目识别点，并响应工作台的减少动态偏好，避免装饰弱化导航层级，同时让项目身份在浅色、深色主题下保持一致。

首页、我的知乎、研究、成果各自保留自己的筛选、选中对象和阅读位置。新增顶层入口只对应值得独立完成的任务；某条内容的详情、一个筛选条件或研究中的步骤使用板块内导航。

### 众声

众声回答的问题是“**一个议题，知乎上大家有哪些不同说法**”。用户只输入议题文本或粘贴知乎问题链接，不选择模式；页面把说法和它的来路摆出来。

- **单位是议题，不是问题也不是关键词。** 一个议题在知乎上可能落在一个具体问题上（有人问过，大家在同一个问题下吵），也可能没有单一落点（讨论散在多个问题里）。这两种是同一件事的两种客观形态，由检索结果判定，不让用户选。
- **说法带立场，也带来路。** 每条说法由看山依据来源摘要聚成，列出支撑它的来源；来源标明是「该问题下的回答」还是「别处的相关讨论」，不混为一谈。
- **落点是加分项，不是前提。** 检索结果里同一问题命中达到阈值才判为落点：落点问题下的回答是主体（常驻），别处的讨论是补充（默认折叠）。没有落点就如实写明“讨论分散在多个问题”，并把全部来源按相关讨论呈现，不假装锚定。落点条允许用户改看别的候选问题。
- **也接受直接给定的问题链接。** 粘贴知乎问题或回答链接时，目标是那个问题本身：跳过落点判定，直接读它下面的回答为主体。问题回答接口不返回问题标题，用首条回答的片段反查一次站内搜索补齐标题，顺带得到该问题之外的讨论作为补充；反查不到标题也不影响主体。
- **额度是稀缺资源。** 问题回答接口每日额度与热榜同量级，只在已判定落点时调用，并有缓存；不随浏览自动触发。直答聚类对送入的来源条数有硬上限（送入过多会退化），因此主体与补充需按上限分配。
- **参数只给预置项。** 提问卡片下提供两个预置选择，不开放自由填写：检索范围（仅知乎站内 / 补充全网）与时间范围（不限时间 / 近 7 天 / 近 1 月 / 近 3 月）。时间范围只在选择补充全网时生效——站内搜索没有时间过滤。补充全网时，全网来源占用固定的补充名额，站内讨论仍是主体。
- **入口与呈现沿用深度研究的语言。** 入口是居中的提问版心（图标 + 大标题 + 建议议题卡 + 提问卡，看山趴在提问卡右上沿）；结果按报告式分节呈现：眉题、议题大标题、来源统计、落点条、分歧与共同、编号说法分节、发丝线来源列表。结果页提供「换个议题」回到提问态，保留议题与参数。

## 3. 首页信息流

### 默认内容

首版复用公共热榜与明确的知乎主题检索。没有已选主题时先展示热榜；用户可以主动调整内容偏好，内容偏好的入口保持轻量。首页不自动把每条热榜展开为多轮检索，不因浏览触发模型分析。

问题、回答与文章均可进入流，但必须来自真实返回。热榜目前只提供问题与文章，回答需要来自支持该类型的检索。可先完成热榜信息流，再接入主题检索；每一阶段如实说明覆盖范围，不以示例回答填充真实频道。类型筛选随可靠数据的覆盖逐步开放，不常驻尚不支持的频道。

热榜是默认种子，主题检索由用户在首页检索框主动发起，两者是同一内容流的两个频道。检索框提供预置的检索范围（仅知乎 / 补充全网）：默认只读知乎站内，用户显式选择后全网结果才作为补充进入流，去重不修改原始出处链接。类型筛选只作用于主题检索——热榜不返回类型，界面不为热榜提供筛选。

热榜额度是全站最紧的一项（100 次/天），因此由服务端持有共享缓存并合并并发请求；本地与桌面运行面另做落盘，重启后仍能显示上一批真实获取过的内容。上游失败或额度耗尽时保留上一批并标注其真实获取时间，不伪装成刚获取；没有缓存可回退时如实说明失败并给出可走的路径，不用空白或示例内容掩盖。

### 首页问答

检索框同时承载第二条通路：把同一个输入交给知乎直答，得到一次快速回答。这是独立于深度研究 Pro 的产物——不取证、不产生来源引用、不进证据体系。面板头部固定标注「直答生成，未附原始来源」（沿用 ADR-0007 对快答产出的披露要求），正文下方固定标注「知无不言也可能会犯错，请核查重要信息」，并给出转入众声看一个议题下不同说法的入口；不在首页把提问变成研究对象。

档位只有快速与深度思考两项，对应直答的 fast 与 thinking 模型，由用户在面板内切换；切换后按同一问题重新提问。回答面板可收起，「众声」把当前问题带进众声并保留议题。

内容流默认不混入个人研究日志或收藏统计；研究进展与成果只在深度研究板块呈现。

### 一条内容的结构

| 层级 | 常驻内容 | 展开或进入详情后 |
| --- | --- | --- |
| 识别 | 实际可得的出处、作者、内容类型 | 完整来源信息 |
| 阅读 | 标题、两至三行原始摘要；有价值时展示来源缩略图 | 更完整的可得摘要及原文入口 |
| 操作 | 阅读原文；次要的“深入研究”入口 | 在研究页补充问题、范围与目标 |
| 补充 | 只有影响当前阅读判断的信息 | 互动数、采集信息等次要字段 |

标题进入阅读，不能默认启动研究。接口只有摘要时，阅读面明确其内容范围，并提供原文链接；不自动生成替代全文。原文按桌面壳既有规则交给默认浏览器打开。

缺少作者、摘要或图片时按真实字段排版，不用占位段落、空图片框或自拟作者补齐版式。较长题目默认最多两行，阅读入口可获得完整标题。没有可靠类型的内容仍可出现在“全部”，不根据标题猜测其为回答或文章。

### 排序、去重与刷新

首版使用可解释的规则：保留各来源集合的原有顺序；多组内容合流时按稳定轮换展示，不跨查询比较不可比的相关性分值。先验证可读性与内容供给，再考虑个性化排序。

来源身份沿用产品的既有规则，应用层负责去重与缓存。为去重做的标准化不修改保存的原始出处链接。浏览缓存与研究证据快照有不同用途；进入研究后按既有命令取得可引用的证据。

一批内容在阅读期间保持顺序。用户主动刷新时获取新批次，有新内容再由用户选择更新；返回首页恢复本次阅读位置。没有可靠新增判定时使用“内容已更新”，不编造新增条数。

根据真实游标决定能否继续加载。数据耗尽显示“本批内容已读完”，保留刷新与搜索的路径；不通过重复内容制造无限信息流。

### 首页与研究入口的范围

首页提供连续条目和轻量类型筛选，复杂条件不常驻首页。首页承载热榜种子与用户主动发起的主题检索，复杂检索条件属于深度研究入口，需要主动探索时从那里进入，不在首页展开入口矩阵。

首页搜索默认面向知乎内容，结果就地呈现；深度研究入口承接需要多来源取证的问题。输入词、范围、结果与返回位置完整传递，不只跳到一个空页。

## 4. 跨板块衔接

| 动作 | 携带的上下文 | 目标行为 |
| --- | --- | --- |
| 内容 → 研究 | 内容身份、出处、用户选定的题目 | 打开待完善的研究入口；提交后才创建或启动任务 |
| 研究 → 报告 | 研究任务身份与报告身份 | 在当前研究任务内直接打开报告 |
| 报告 → 来源 | 保存的报告与证据引用 | 查看报告引用的证据，避免悄悄换成新抓取内容 |
| 任意板块 → 返回 | 来源页面、筛选条件、选中条目与阅读锚点 | 恢复用户离开的位置 |

跨板块导航与启动业务操作分开：看内容、切页面、打开任务不会自动授权新研究或新外部调用。目标对象已删除或无法访问时给出解释和返回路径，不用另一条示例对象替代。

新的导航目标逐步采用现有类型系统中的明确目标，避免仅靠标题字符串定位对象。返回上下文属于前端会话状态，不能成为研究进度的另一份事实来源。

研究完成或需要处理时，可在研究入口给出轻量提示；点击定位具体对象。通知不强制打断首页阅读，也不把整张任务列表搬到首页。

## 5. 页面形态与密度

| 页面 | 主要形态 | 详情出现方式 |
| --- | --- | --- |
| 首页 | 单列知乎内容流与一次直答快答 | 内容进入阅读；需要可核对引用时转众声 |
| 研究 | 列表进入单个任务，按任务状态呈现内容 | 计划、来源、过程按需展开 |

不要求每页共用同一种卡片外壳；复用排版、按钮、来源条目与阅读组件，具体布局由内容决定。

首页的初始设计范围：导航约 200–224 CSS px，阅读列约 760–860 CSS px，页面边距 24–32 px；条目标题 18–20 px，摘要 14–15 px、行高约 1.65，元信息 12–13 px。尺寸需在现有主题和实际窗口中校准，不直接换算截图像素。

颜色、字体、阴影、焦点和动效继续使用工作台[主题令牌](../../src/workbench/src/personal-workbench/workbench/styles/theme.css)。新增尺寸若值得复用，落为对应语义或组件令牌；不在本文维护第二套颜色值。

降低容器层数与重复标签。条目分隔用轻边界或稳定留白；只有需要用户处理的状态加强调。图片比例保持克制，原有品牌插画与问候可保留，不增加额外首屏装饰区。

窄窗口先收起非必要辅区和导航，再让阅读列占满可用宽度。页面以主阅读区域滚动，返回时恢复位置；核心动作不能只在悬停时出现。按真实内容宽度设断点，不沿用已经不适合当前外壳的预览断点。

## 6. 状态与可用性

| 场景 | 要求 |
| --- | --- |
| 首次加载 | 展示少量与条目形态一致的占位，避免空白页面 |
| 刷新中 | 保留已有内容；请求结束前不清空正在阅读的流 |
| 旧请求晚返回 | 不能覆盖用户已经切换的筛选或查询 |
| 某个内容渠道失败 | 保留成功渠道，明确失败范围和重试入口 |
| 全部渠道失败 | 显示真实失败；有缓存则说明缓存时间，不伪装成刚获取 |
| 空结果或数据耗尽 | 两种语义分别表达；重试不会自动编造内容 |
| 凭证或授权缺失 | 在需要外部能力的位置说明；本地资料与已保存成果仍可读 |
| 长标题、无摘要、无作者 | 不破坏布局，保留真实可得信息和明确阅读入口 |
| 返回、主题切换、键盘操作 | 保留必要上下文、可见焦点与完整操作路径 |

普通简报保持手选证据语义；深度研究在批准范围内按 Workflow 自动取证，报告在任务内直接呈现。两者的任务状态以产品 DTO 为准，界面不能用定时器、假百分比或导航位置推算进度。详细失败与恢复不变量继续由架构 ADR 和后端契约维护。

## 7. 扩展与实现边界

公共外壳负责导航、主题和视图容器。板块负责自己的页面组合、筛选与专属交互；业务规则继续由应用层拥有。共享阅读与来源组件不包含特定板块的任务调度逻辑。

导航名称、图标、分组与基础布局策略应集中在一份静态定义中，供侧栏、顶栏和页面标题使用。页面组件在组合入口登记，并保持各自错误边界。新增板块仍需实现页面与应用能力接入，不能把“可扩展”描述成只写一行配置。

采用现有 React、TypeScript、导航 reducer、React Query、Zod 与产品应用边界，按实际需要逐步整理。暂不引入动态插件装载、微前端、通用面板编辑器或另一套 Agent 运行时。

应用层统一内容聚合、来源身份、缓存和错误语义；页面消费产品 DTO。首页与个人面的缓存键包含实际查询范围，授权数据包含身份范围。Mastra 类型与知乎原始响应均不进入页面。

新增板块应满足：

1. 说明独立的用户任务、页面入口及数据归属。
2. 登记导航与页面，明确跨板块目标和返回行为。
3. 接入已有应用命令；确需新公共契约时在其 owner 处设计。
4. 覆盖空、加载、失败及必要的授权状态。
5. 验证现有导航、资料读取和研究主链路不受影响。
6. 首页保持信息流结构，不因新板块增加摘要面板。

## 8. 实施顺序与验收

当前情况来自代码检查：首页由热榜种子与主题检索内容流和直答快答面板组成，网页端与工作台共用同一组内容流组件；首页已不再承载研究卡片，研究入口与进展只在深度研究板块。简报库入口已移除，研究报告从研究任务内打开。曾把热榜、收藏、创作、关注并列铺开的“发现”页已删除，这四类读取器仍由“我的知乎”复用；现有导航主要携带视图名，任务行尚未定位具体研究。上述行为是实施起点与已完成部分的核对结果，不能写成全部改造完成。

| 阶段 | 改动范围 | 完成标准 |
| --- | --- | --- |
| 1. 入口与边界 | 统一导航元信息；取消聚合式发现入口；按方案核对可见名称 | 侧栏、顶栏、标题一致；切换不意外打开会话或丢失已有对象 |
| 2. 首页内容流 | 复用内容适配和应用查询；透出真实摘要、出处与可选图片 | 首页可浏览真实可得内容；类型、缺失字段与分页符合来源能力 |
| 3. 搜索 | 补齐查询传递及局部状态；检索条件只由搜索页与研究入口承接 | 查询不会丢失，结果有明确范围；首页不常驻复杂条件 |
| 4. 研究与报告衔接 | 带对象身份跳转；恢复阅读位置；核对来源版本 | 从内容进入研究、从研究任务打开报告并核对来源都到达正确对象 |
| 5. 后续板块 | 逐个完善资料整理、外部知识库等能力 | 独立验收；现有板块和首页结构保持稳定 |

首页内容流与快答依赖的能力、额度与缓存边界见 [开放平台能力清单](../开放平台能力清单.md)；本节只维护首页的阅读结构，不复制能力清单里的额度与上游契约。

每一阶段只改对应模块。现有通用面板 CSS 同时影响研究与简报页面，首页调整使用明确的组件边界，避免全局放大样式误伤其他页面。

本轮方案优化只更新文档，不安装依赖、不更改公共命令、数据格式或研究状态机，因此不新增架构 ADR。实施若涉及这些边界，遵循开发维护规则在对应 owner 更新设计与最小不变量测试。

实施验收使用针对性的类型检查、受影响构建与 `git diff --check`；仅在行为风险需要时补测试或定点 UI 检查，不以全量测试替代针对性验证。必须检查：内容流真实范围、对象定位、跨页返回、旧响应覆盖、已有研究恢复、共享样式影响和新板块接入成本。

首页布局示意保存在本地设计工作目录，不纳入版本控制。示意图用于说明阅读节奏，数据与摘要是设计示例，命名和实现规则以本文与术语 owner 为准。
